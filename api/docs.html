MaudeSignal connector API

MaudeSignal reads FDA MAUDE adverse-event reports, recalls and 510(k) records for AI-enabled medical devices and flags what changed. This API gives a Meta Muse custom connector five read-only tools over that data. Every answer is a short summary that can be read aloud, a list of facts that each carry an openFDA or record link, a fixed advisory line, and where the data came from.

Advisory line on every answer: {{ADVISORY}}

The five tools

All are read-only. Send your key in the X-API-Key header. Never put it in the URL: a request with a key-like query parameter is refused with 400.

ToolRequestInputWhat you get
what_changed_this_weekGET /v1/tools/what_changed_this_weekproduct_code (optional, 3 letters, e.g. LLZ)The latest stored week from the demo snapshot, with its dates. A code outside the stored set is checked live on openFDA.
check_device_typeGET /v1/tools/check_device_typeproduct_code (3 letters)Live openFDA report counts for any device type, using the same four rules, windows and thresholds as the weekly detector. If openFDA cannot be reached for a stored code, the stored snapshot answers and says so.
askPOST /v1/tools/ask (body: {"question": "..."}, 3 to 500 characters)questionA Muse Spark answer built only from stored records. Each sentence goes through the claim gate. Sentences the gate did not verify are listed under withheld and are never in speakable. Without a model key, or after the cost cap, the closest recorded answer is returned and labelled recorded. POST only because the question travels in the body; nothing is written.
get_reportGET /v1/tools/get_reportreport_id (MAUDE report id)Key fields and the start of the narrative of one stored report, with its record link.
recallsGET /v1/tools/recallsproduct_code (3 letters)Stored openFDA recalls for the code, newest first.

Authentication

Header name: X-API-Key. Keys are created by the operator (see the deploy notes) and are read-only. A missing or wrong key gets 401 with the same body either way. Repeated wrong keys from one address get 429. The key is never written to a response, a log or the audit log; the audit log names a caller by the first 8 hex characters of the key's SHA-256.

Rate limits and cost cap

Data provenance

Every answer says where it came from. stored_demo_snapshot: the committed demo copy of openFDA data, with the date it was fetched; not live. live_openfda: counts fetched at the UTC time in queried_at_utc. recorded_answer: a real, gated earlier run of the copilot. live_model: a Muse Spark answer from this call. MHRA (UK) alerts, where present, are regulator context only and never counted in a MAUDE number.
