Privacy

What MaudeSignal does with data

MaudeSignal is an advisory triage aid for quality and regulatory review of public FDA device data. It is not medical advice, it is not clinical decision support, and it files nothing with FDA.

There is no personal data and no patient data in this service by design. Please do not type patient details anywhere.

The short answers

Does it collect personal data?
No. There are no accounts and no sign-up, and nothing asks for a name or an e-mail address. Feedback is free text without a name. Free text is checked for e-mail addresses, phone numbers, "MRN" with digits and dates of birth before it is stored (a guard, not a guarantee).
Does it handle patient or health data?
No. The data it serves is public openFDA data (adverse-event reports, recalls, 510(k) records) that FDA has already de-identified.
Where is data processed and stored?
On Vercel, in the United States: serverless functions in region iad1 (Washington, D.C.). The workspace you are reading is static files served by Vercel. Feedback notes and visit counts are kept in a private Vercel Blob store. Snapshots of public data are part of the deployment itself.
Who else handles data?
  • Vercel: hosting, serverless functions, private Blob storage, and Web Analytics on this website.
  • Meta Platforms, through the Meta Model API: only for the "ask" tool, and only when live answers are switched on. It receives the question text (and the earlier turns the page sends with it) plus the checked facts needed to answer. With live answers off, or when the daily cost limit is reached, a recorded answer is shown and nothing is sent to Meta. What Meta does with API requests is governed by Meta's own terms for the Meta Model API.
  • openFDA (api.fda.gov, run by FDA): the public data source. It receives only a three-letter product code or a report number, never a question.
  • Public news and web sources, only when you press "Search outside sources": the server asks GDELT, FDA feeds and other public feeds for pages that match a product code and a few short device terms, then fetches those public pages.
  • Resend, only if the owner turns on e-mail notifications of new feedback; it is off unless configured.
What is logged?
For each tool call: the key id (a keyed hash; never the key itself), the tool name and the time, plus the public identifiers used (a product code or a report number), a hash of the answer and counts of facts and withheld sentences. The text of a question is not kept: only a hash of it and its length. Feedback entries hold a rating, your free text, the page and an optional personal link code, with no name, no e-mail, no IP address and no browser identifier. Visit entries hold the page, the time and the link code. For rate limiting, a counter keyed by a salted hash of the network address exists only for the length of the limit window. Vercel also keeps its own request logs (method, path, status, address, time) under its own retention period.
How long is it kept?
No automatic deletion period is set yet for audit, feedback or visit entries. Rate-limit counters last only for their window, and anything held in a server's memory disappears when the instance stops. Entries are deleted when you ask (below). Vercel's own request logs follow Vercel's retention, which MaudeSignal does not control.
How do I ask for deletion?
E-mail kondapallysaicharan63@gmail.com with the key id or the personal link code your entries are tied to. Because no name or e-mail is stored, entries can only be found by that code or key id. They are deleted and you get a reply when it is done.
Is it sold, used for advertising, or shared for marketing?
No. It is not sold, not used for advertising or profiling, and not shared with anyone except the services listed above, which handle it only to run MaudeSignal. MaudeSignal does not use it to train models.

Scope

U.S. FDA (openFDA) data only. UK MHRA alerts appear only where an answer labels them "MHRA (UK)". Mentions found on news sites and the public web are shown in a separate box, marked "Unverified — not checked against FDA records", and are never mixed with the checked FDA facts.
