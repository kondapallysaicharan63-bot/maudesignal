Privacy

What MaudeSignal does with data

There is no personal data and no patient data in this service by design. Please do not type patient details anywhere.

What does this service do with data?
It gives read-only access to public FDA device data (openFDA: adverse-event reports, recalls, 510(k) records) and, where a result says so, to device alerts from the UK MHRA, always labelled as UK. It is an advisory triage aid for quality and regulatory review.
Is any personal or patient data collected?
No. The data served is public and already de-identified by FDA. There are no accounts and no sign-up. Do not type patient or personal details into a question: the live routes refuse text that looks like a name with a title, an age, an email address or a phone number, and nothing is kept when they do.
Where is data processed and stored?
The service's functions run on Vercel in region iad1 (Washington, D.C., United States), as set in the project's vercel.json. Feedback entries, page-visit entries and the daily spend records are stored in a private Vercel Blob store. The region of that store is chosen when the store is created in the Vercel dashboard; the code does not check it, so this page does not state it. The other services named below (Meta Model API, Resend, GDELT, and Upstash if the operator sets it up) process what they receive in their own locations, which this service does not control.
Who else handles data (subprocessors)?
Vercel (hosting, runtime logs and Blob storage). Meta Model API: only when live answers are switched on, for the live ask, voice and label routes; the question text, the voice clip or the label photo is sent once to produce the answer when live answers are on, and is not stored by this service. Resend (email): only if the operator turns on email for new feedback; the email carries the feedback fields, no name and no address. Upstash (Redis): optional, only if the operator sets it up; it then holds the audit log, the rate-limit hashes and the daily cost ledger (no question text, no address, no name). Public data sources that this service reads: openFDA, GOV.UK (MHRA alerts), GDELT and FDA public feeds (for the outside-mentions search). These send us public data; we send them a product code or a search term, never a person's details.
What is logged, and for how long?
Per tool call: a key id (a keyed hash of the key, never the key), the tool name, the time, the status and the cost. Never the text of a question: for ask, only a hash and a length are recorded. Feedback is stored without names (role and quote consent only). A page visit stores the referral code, the page and the time. This service never stores an IP address: before any rate limit or counter sees it, the address is replaced by a keyed hash, which is held in memory (or in the operator's Redis store, if one is set up) only to apply limits, for at most twice the limit window (two days for daily counters). Vercel's own request logs may include the address; they are kept by Vercel for Vercel's runtime-log retention for this plan. Feedback and visits are kept until the hackathon review ends, then deleted on request or by 30 November 2026.
Cookies, tracking, sale of data, advertising?
No tracking cookies. No sale of data. No advertising and no use of data for ads. The separate web app may use Vercel Web Analytics for page-view counts, which sets no cookies.
Not medical advice, nothing filed
Nothing here is medical advice or clinical decision support. Nothing is filed with FDA or any other regulator. This is not an FDA-cleared device. It is an open-source project by Saicharan Kondapally.
How do I ask for deletion?
Write to the contact address (shown on /privacy, read from MAUDESIGNAL_CONTACT_EMAIL at runtime; if it is not set, the GitHub issues URL is shown) and give the referral code you were sent. Feedback and visits carry no name, so the code is how an entry is found. Entries are deleted on request.

Contact for deletion and questions

The contact address is shown on the service's own privacy page, https://maudesignal-api.vercel.app/privacy (it is read from a setting at run time and is not published in this repository). You can also open an issue at GitHub issues; do not put personal details in an issue.

Scope

U.S. FDA (openFDA) data only. UK MHRA alerts appear only where an answer labels them "MHRA (UK)". Mentions found on news sites and the public web are shown in a separate box, marked "Unverified — not checked against FDA records", and are never mixed with the checked FDA facts.

These answers are copied word for word from the Data questionnaire in docs/hackathon/MUSE_CONNECTOR.md, which is also what the Meta Muse connector form uses.
